# MLB 카테고리별 매출 비중 분석 (27SS IMC PLAN 대비)

작성자: MLB MKT 채승룡 · 데이터 조회일: 2026-11-16

MLB 국내·중국 월별 × 아이템 × 시즌구분 매출(2025-01 ~ 2026-11-15)로 만든 대시보드입니다.

- 1차: 시즌별(25SS·26SS) 카테고리 매출과 비중
- 2차: 월별 매출 추이, 카테고리별 2025 vs 2026 패턴, 피크월·푸시 시점 제안
- 3차: 월별 피크 아이템 Top 3 타임라인, 막대그래프, 꺾은선 그래프 (기준 연도: 2개년 평균 / 2025년 / 2026년)

## 폴더 구성

```
index.html                         대시보드 페이지 (이 파일 하나로 동작)
data/category_sales_monthly.json   원본 로우데이터 (CSV로 두어도 됨: category_sales_monthly.csv)
.nojekyll                          GitHub Pages가 파일을 그대로 쓰게 하는 빈 파일
README.md                          이 안내문
```

## 데이터 형식

한 줄이 `국가 × 월 × 아이템 × 시즌구분` 하나입니다. JSON은 객체 배열, CSV는 아래 열 이름을 헤더로 씁니다.

| 열 | 뜻 | 예 |
|---|---|---|
| country | 국가 | 국내, 중국 |
| ym | 연월 | 2026-03 |
| period | 시즌 구간 (2~8월만) | 25SS, 26SS, 그 외 빈칸 |
| l1 / l2 / l3 | 구분 / 대분류 / 세부 카테고리 | 용품 / 모자 / 볼캡 |
| item / item_nm | 아이템코드 / 아이템명 | CP / 볼캡 |
| season_type | 상품 시즌구분 | SS, FW, N |
| amt | 실판매액(원, 중국은 원화 환산) | 123456789 |

데이터를 새로 뽑으면 `data/` 폴더의 파일만 바꿔 올리면 페이지가 그대로 새 숫자로 그려집니다.

## GitHub에 올려서 링크 만들기 (GitHub Pages)

1. GitHub에서 새 저장소를 만듭니다 (예: `mlb-27ss-imc-dashboard`).
2. 이 폴더의 파일을 모두 올립니다. 웹에서는 **Add file → Upload files**로 폴더째 끌어다 놓으면 됩니다. `data/` 폴더와 `.nojekyll`도 함께 올라가야 합니다.
3. 저장소의 **Settings → Pages**에서 Source를 **Deploy from a branch**, Branch를 `main` / `/ (root)`로 두고 Save를 누릅니다.
4. 1~2분 뒤 같은 화면에 링크가 나옵니다: `https://<계정명>.github.io/<저장소명>/`

> index.html을 PC에서 더블클릭해 열면 브라우저 보안 때문에 data 파일을 읽지 못합니다. GitHub Pages 링크로 열거나, 폴더에서 `python -m http.server` 를 실행한 뒤 `http://localhost:8000` 으로 여세요.

## 공개 범위 주의

- 무료 계정의 GitHub Pages 사이트는 **링크를 아는 누구나** 볼 수 있고, 저장소가 Public이면 `data/` 원본도 그대로 내려받을 수 있습니다.
- 사내 매출 데이터이므로, 회사 정책상 외부 공개가 어렵다면 **회사 GitHub 조직(Enterprise)의 Private 저장소 + 접근 제한 Pages**를 쓰거나, 사내 보안 담당과 먼저 확인하세요.

## 기준과 한계

- 시즌 기간: SS = 2~8월, FW = 9월~다음 해 1월로 가정했습니다.
- 계절지수 = 그 달 매출 ÷ 해당 아이템 월평균 × 100. 순위는 국가 매출 상위 25개 항목만 대상으로 합니다.
- 2026년은 10월까지 집계했습니다(11월 진행 중).
- 그래프 라이브러리 d3를 jsDelivr CDN에서 불러옵니다. 인터넷이 막힌 환경에서는 그래프가 그려지지 않습니다.
